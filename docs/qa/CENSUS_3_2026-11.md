## 2. Sample: 300 of 1,440

#241 targets about 300 articles. Census #2 rated the whole cohort. Here the cohort is about 5x
the target, so `rate_census.py build` gained `--size N`, which keeps the **first N of the same
seeded shuffle**. The result is still one stratum with equal weights (`population 1440,
sampled 300, weight 4.8`): a simple random sample, so proportions need no reweighting. The
stratified N05 design was not reused: census #2 dropped it because unequal weights made one
football row count 13x a basketball row.

- **Seed 20261101**, which differs from census #2's 20260916. `RatingsStore` refuses a
  ratings file whose seed differs from the sample's, so census #2's ratings cannot be loaded
  against this sample by mistake.
- **Extendable.** A later `build --size 1440 --seed 20261101` on the same frozen copy is a
  superset in the same order (tested), and the ratings already given carry over. Rebuilding
  this sealed census requires `--keep-sealed-from ../docs/qa/census3_sample.json`. Without it,
  `build` refuses to overwrite the sample, because it would drop the held-out split. With it,
  the split is carried forward unchanged and **every extension row joins the fit half** (tested).

Command (from `backend/`, with `DATABASE_URL` pointing at a scratch copy of the frozen DB):

```
python scripts/rate_census.py build --since 2026-10-11 --size 300 --seed 20261101 --out ../docs/qa/census3_sample.json
```

## 3. Held-out half: sealed, read once (pre-registered before any rating)

#241: no calibration from census #3 without a held-out half. Owner decision (2026-11-01):

- **The owner rates all 300 rows**, in one page, blind both to the engine and to which half a
  row is in. The page receives only title, subtitle, source, date and link
  (`census_rating.rater_view`). The split lives in a separate file that the page never reads.
- **The held-out half and its ratings stay out of all tuning, calibration and rule design.**
  They are used **once**, for a final evaluation.
- **The half:** `census3_heldout_ids.json`, 150 ids, fixed before any rating.
  `census_calibration_fit.split()` (#237, seed 237) over all 300 sample ids; the fit half is
  the other 150. The sample names this file and the sealed ratings file in
  `meta.sealed_heldout`. A test pins both the split and the pointer.

**How it is enforced:**

| step / tool | what it does with held-out ratings |
|---|---|
| rating the **last** row on the page | seals automatically: the 150 held-out ratings move to `census3_heldout_ratings.json`, a raw copy of the fit half goes to `census3_fit_raw_ratings.json`, and `census3_ratings.json` keeps the fit half only. After that the page serves the fit half only, so undo can never put a held-out rating back. (A page started from an older copy of the tool cannot do this; then run `seal` by hand first.) |
| `rate_census.py seal` | the same, by hand. Refuses before all 300 are rated, refuses ids outside the sample, and refuses a second run. It is recoverable: the census ratings file is written last, so after an interruption a re-run completes the seal (it checks the held-out ratings still match). |
| `rate_census.py serve` | never re-asks a sealed row. Before sealing it asks every row and shows nothing about the split. |
| `rate_census.py review` | excludes held-out ids even from an unsealed file, and refuses the sealed file unless `--final-heldout-eval` (the optional final-evaluation re-rate, §5.3). `merge-review` never writes into the sealed file. |
| `census_checks.py` | drops held-out ratings unless `--final-heldout-eval`; its listings tag held-out rows "held-out: do not act" and hide their decision and rating. |
| `census_calibration_fit.py` | drops held-out ratings, even ones passed via `--review`, unless `--final-heldout-eval`; with a sealed census its halves are the pre-registered ids, not a fresh split. |
| `eval_stats.py census`, `corpus_rerun_diff.py compare --ratings`, `llm_bakeoff.py --ratings/--review` | refuse a sealed ratings file (it carries a `sealed` marker) unless `--final-heldout-eval`. |
| `feed_ground_truth.py score` / `gate` | **no guard yet**: it scores whatever ratings file it is given. Follow-up once #399 (which owns that script) lands: the same `refuse_sealed` check on its loader. Until then, pass it the sealed file only at the final evaluation. |

**Remaining guards (documented, not code):** if the rating is finished on a copy of the tool
without the automatic seal, `census3_ratings.json` holds both halves until `seal` runs, so run
`seal` before anything else reads or commits the ratings. A census gate (#254) or any repeated
check must be fed `census3_ratings.json` (fit), never the sealed file. A gate is used over and
over, so held-out ratings in a gate would no longer be held out.

## 4. The four #241 checks: engine side, whole cohort

`scripts/census_checks.py` (read-only) scores the whole cohort the same way `build` does and
lists the rows each question is about. With `--ratings` it also prints the owner's rating where
one exists. These are lists for the owner to read, not verdicts.

1. **`club_governance` pushes:** does every push report a concrete step?
2. **Executives (`exec:*`):** any false resolution? A title mention implies Maccabi Tel Aviv;
   a subtitle-only mention is sport evidence only.
3. **Israeli basketball cups:** are cup stories visible?
4. **Subtitle-only "לקראת":** is such a story still typed `schedule`, or hidden?

**Engine-side results are withheld until rating is done and sealed**: per-check counts would
narrow down engine decisions on sample rows. Cohort-level result already public: no
subtitle-only "לקראת" row is typed `schedule`, so the #224 title-local rule held in production.

## 6. How to rate and score

Run everything from a checkout of this branch, not from the live worker's checkout. The rating
page reads **no database**: it serves the sample JSON and writes only the ratings JSON, after
every keypress. To keep the rating blind, rate before reading past the banner or opening
`census3_sample.json`: the file carries the engine's decisions, though the page never shows
them.

**Rating (about 12–15 minutes):** census #2 took about 30 minutes for 713 rows, roughly 2.5 s
per row.

```
cd backend
python scripts/rate_census.py serve --sample ../docs/qa/census3_sample.json --ratings ../docs/qa/census3_ratings.json
```

All 300 rows are rated in this one page; nothing on it says which half a row belongs to.
Rating the last row seals the held-out half automatically (§3). If the page was started from an
older copy of the tool, run `seal` by hand (step 1) before anything else reads the ratings.

**Scoring.** PowerShell, from `backend/`, against a fresh scratch copy of the frozen DB:

```
$py   = "<venv>\Scripts\python.exe"
$copy = "$env:TEMP\census3_score.db"
Copy-Item C:\Users\HOME\Documents\signal-sports-preserved\2026-11-01-m11\frozen_20261101.db $copy
$env:DATABASE_URL = "sqlite:///" + ($copy -replace '\\','/')
$env:CLASSIFICATION_PROVIDER = "disabled"; $env:TRANSLATION_PROVIDER = "disabled"
$env:PYTHONIOENCODING = "utf-8"   # feed_ground_truth prints box-drawing characters

# 1. SEAL. Automatic on the last rating; by hand only if the page could not (it refuses a second run)
& $py scripts/rate_census.py seal --sample ../docs/qa/census3_sample.json --ratings ../docs/qa/census3_ratings.json
# 2. Commit census3_ratings.json (fit), census3_fit_raw_ratings.json (fit, raw, never edited)
#    and census3_heldout_ratings.json (sealed, raw).
# 3. Stored-fact decisions for the SAMPLE rows, the four checks, and metrics by classification path
& $py scripts/census_checks.py --since 2026-10-11 --sample ../docs/qa/census3_sample.json `
    --ratings ../docs/qa/census3_ratings.json --snapshot-out $env:TEMP\census3_stored.json
# 4. Re-rate before acting: a blind re-rate of fit rows where engine and owner differ by >= 2 notches.
#    It re-rates sample rows only (never an out-of-sample row) and never a held-out row.
& $py scripts/rate_census.py review --sample ../docs/qa/census3_sample.json `
    --ratings ../docs/qa/census3_ratings.json --out ../docs/qa/census3_review_sample.json `
    --snapshot $env:TEMP\census3_stored.json
& $py scripts/rate_census.py serve --sample ../docs/qa/census3_review_sample.json `
    --ratings ../docs/qa/census3_review_ratings.json
& $py scripts/rate_census.py merge-review --ratings ../docs/qa/census3_ratings.json `
    --review ../docs/qa/census3_review_ratings.json
# 5. DEVELOPMENT numbers: fit half, reviewed (§5.1, §5.2)
& $py scripts/feed_ground_truth.py score --ratings ../docs/qa/census3_ratings.json `
    --sample ../docs/qa/census3_sample.json --live --out ../docs/qa/census3_score.json
& $py -I ../.claude/skills/signal-quality-eval/scripts/eval_stats.py census $env:TEMP\census3_stored.json `
    --ratings ../docs/qa/census3_ratings.json
& $py scripts/census_checks.py --since 2026-10-11 --sample ../docs/qa/census3_sample.json `
    --ratings ../docs/qa/census3_ratings.json --out $env:TEMP\census3_checks.json

# 6. FINAL EVALUATION, ONCE (§5.3), only when the owner calls it, after all tuning is frozen.
#    6a. Primary, like for like: fit RAW vs held-out RAW
& $py -I ../.claude/skills/signal-quality-eval/scripts/eval_stats.py census $env:TEMP\census3_stored.json `
    --ratings ../docs/qa/census3_fit_raw_ratings.json
& $py -I ../.claude/skills/signal-quality-eval/scripts/eval_stats.py census $env:TEMP\census3_stored.json `
    --ratings ../docs/qa/census3_heldout_ratings.json --final-heldout-eval
& $py scripts/feed_ground_truth.py score --ratings ../docs/qa/census3_heldout_ratings.json `
    --sample ../docs/qa/census3_sample.json --live --out ../docs/qa/census3_heldout_score.json
#    6b. Whole sample (300), raw ratings of both halves
& $py -I ../.claude/skills/signal-quality-eval/scripts/eval_stats.py census $env:TEMP\census3_stored.json `
    --ratings ../docs/qa/census3_fit_raw_ratings.json --review ../docs/qa/census3_heldout_ratings.json --final-heldout-eval
#    6c. By classification path, one run per column (fit raw / held-out raw / whole sample raw)
& $py scripts/census_checks.py --since 2026-10-11 --sample ../docs/qa/census3_sample.json `
    --ratings ../docs/qa/census3_fit_raw_ratings.json
& $py scripts/census_checks.py --since 2026-10-11 --sample ../docs/qa/census3_sample.json `
    --ratings ../docs/qa/census3_heldout_ratings.json --final-heldout-eval
& $py scripts/census_checks.py --since 2026-10-11 --sample ../docs/qa/census3_sample.json `
    --ratings ../docs/qa/census3_fit_raw_ratings.json --ratings ../docs/qa/census3_heldout_ratings.json --final-heldout-eval
#    6d. Optional, reported alongside, never replacing the raw numbers: blind re-rate of held-out >= 2-notch gaps
& $py scripts/rate_census.py review --sample ../docs/qa/census3_sample.json `
    --ratings ../docs/qa/census3_heldout_ratings.json --out ../docs/qa/census3_heldout_review_sample.json `
    --snapshot $env:TEMP\census3_stored.json --final-heldout-eval
& $py scripts/rate_census.py serve --sample ../docs/qa/census3_heldout_review_sample.json `
    --ratings ../docs/qa/census3_heldout_review_ratings.json
& $py scripts/census_checks.py --since 2026-10-11 --sample ../docs/qa/census3_sample.json `
    --ratings ../docs/qa/census3_heldout_ratings.json --ratings ../docs/qa/census3_heldout_review_ratings.json `
    --final-heldout-eval
```

**Out-of-sample rows** (engine pushes outside the sample, or anything else outside the 300) are rated,
if ever, in their **own** sample and ratings files, which are never named
`census3_ratings.json` and never passed with `census3_sample.json`. The tools refuse to mix
them in. `seal` and `census_checks.py` reject a ratings file that names an id outside the
sample. `feed_ground_truth.py score` scores only ids that are items of the sample it is given.
`eval_stats.py` meets decisions only through `census3_stored.json`, which holds sample rows
only.

Notes:
- **Use a copy.** Opening a database through the app engine switches it to WAL mode. On the
  2026-11-01 dry run that changed the copy's bytes, but no row. That is why the frozen file is
  never opened directly.
- `--snapshot` makes `review` measure gaps against the engine as of scoring time. Before any
  engine change it equals the decisions recorded in the sample.
- `eval_stats` reads `census3_stored.json`: decisions on **stored** facts, i.e. production
  facts. A `corpus_rerun_diff` snapshot is a rules-only replay and answers a different question.
- Dry runs on 2026-11-01 (scratch copies, placeholder ratings, discarded; no owner ratings
  used or invented): the development sequence end to end, including `seal`, the refused
  second `seal`, the final evaluation and a refused out-of-sample rating. The final-evaluation
  commands added after review (6a–6d) were re-run the same way.
